- **2026-06-24** — **Local self-hosted Overpass integration proven end-to-end** (runbook: [knowledge/runbooks/local-overpass-testing.md](knowledge/runbooks/local-overpass-testing.md)).
  - Stood up wiktorn on the **mirrored** image `registry.hzdr.de/ufz/tb5-smm/met/wg7/osm-services/overpass:latest`, serving a merged **Sachsen + Sachsen-Anhalt + Brandenburg** snapshot (`osmium merge`, 67M nodes / 10.7M ways, border-dedup verified via `osmium fileinfo`). `OVERPASS_DIFF_URL=` empty → snapshot, no update feed.
  - **COSMONAUT needed no code change** — `OVERPASS_URL` was already env-wired in `osm/source.py`. Pointed at the instance via `OVERPASS_URL="http://localhost:12345/api/interpreter"` in `env_dev_mock`; `network_mode: host` makes `localhost:12345` reachable from the worker. **The client POSTs the URL verbatim → it must be the full `…/interpreter` URL**, not the base `…/api` (the `compare_osm_backends.py` spike has the opposite convention).
  - **Results:** tri-state AOI (~7,000 km²) fetch via `OsmDownloader`: 12.6 s / 153 MB peak / 97,674 roads, no throttling (the query class public rate-limits). Small-AOI diff local vs public: **route-equivalent** (802=802 features, 0 m geom delta, identical sensor-routing connectivity). Verified via `./dev_up mock` and `compare_osm_backends.py`.
  - **Found + fixed an osm-services bug:** compose used `${OVERPASS_DIFF_URL:-…germany-updates…}`, so an empty `.env` value did **not** disable auto-updates (`:-` substitutes the default for empty too) — a "snapshot" instance silently ran the germany-updates loop and advanced the DB base ~1 day. Fixed to `${VAR-default}` (no colon). Change is in osm-services; user commits separately.
- **2026-06-08** — Optimized the Overpass-direct backend: **streaming + vectorization**.
  - **Streaming download:** `OverpassSource.stream_ways` (requests `stream=True` + ijson) + new `osm/geojson_writer.py` (`StreamingGeoJsonWriter`, **atomic**: writes `*.tmp`, renames on clean close, discards on error — a failed/partial download never leaves a half-written file) + per-way pyproj projection in `downloader.py` (geopandas dropped from the download path). One way is parsed→transformed→projected→written at a time. **Saxony peak 3.2 GB → 152 MB** (54 s, same 375,293 features). Profiling showed the old peak was `response.json()` (the full parsed tree), not geopandas — so streaming the parse is the lever; clear types / vectorization don't move the peak.
  - **Retry bug fixed (`upload_tasks.py`):** the Overpass-transient retry guard was `if e.response and …` — but `requests.Response.__bool__` returns `response.ok` (False for ≥400), so 429/502/503/504 **never retried** (latent; osmnx used to swallow Overpass errors, direct `requests` exposed it). Fixed to `e.response is not None`. The retry test gave a false positive because it mocked the response with a (always-truthy) `MagicMock`; now uses real `requests.Response` objects.
  - **Vectorized truncate-by-edge:** `shapely.contains_xy` on a prepared polygon instead of per-node `Point` loops — **3.1× faster, +0 MB** (per-way transient).
  - **Fidelity:** streaming output bit-identical to the geopandas path (0.0 m projection delta, identical properties); ijson parse byte-identical to json parse; 9 offline tests green. `way_to_feature` normalizes ijson Decimals to int/float. New dep: `ijson`.
  - **Edit path migrated:** extracted `osm/projection.py` (`project_feature` + `project_features_to_file`); `street_selector.py` now reprojects edits through it (atomic, named CRS header) instead of `osm_downloader.project_and_save` (geopandas). Output byte-identical (0 m delta, 0 property diffs).
  - **Old module deleted + osmnx removed from direct deps:** `cosmonaut_app/osm_downloader.py` is gone (no production importers were left). `compare_osm_backends.py` reworked to a measurement tool + optional `--reference` file diff (no osmnx baseline). `osmnx` dropped from `pyproject.toml`. **But osmnx is still installed transitively** — it's a dependency of `sensor-routing==0.2.6`, so the image/CI is **not** lighter yet; a real drop needs sensor-routing to remove osmnx (raise with Can — it may not actually use it). `osm_cache_patch` and `regenerate_osm_cache.py` already used the new package.
- **2026-06-05 (implementation)** — Built the Overpass-direct OSM backend (`cosmonaut_app/osm/`: `source.py` + `transform.py` + `downloader.py`), resolving the scaling block from the investigation entry below. Key points:
  - **Why it works:** the 12.5 GB was the osmnx networkx graph, which the old pipeline then *un-builds* (`_reconstruct_ways`) back into the OSM way node sequences that Overpass `out geom` returns natively. Direct query → no graph → RAM scales with the road data, not a graph.
  - **Fidelity proven** (`test/fixtures/compare_osm_backends.py`, both backends vs the same Overpass, osmnx cache off): test AOI route-equivalent (0 roads lost, 0 node-set/tag mismatches, **0 m** geom delta, sensor-routing connectivity map identical). Two understood deltas: roundabout start-node rotation (neutral; oneway now inferred osmnx-style) and one track osmnx *drops* (MultiLineString artifact) which the new backend keeps — measured **routing-redundant** (covers 2 points, both already covered; reachable coverage 483 = 483).
  - **Saxony RAM:** 3.2 GB / 77 s / 375k features / 357 MB against self-hosted wiktorn (vs osmnx 12.5 GB). Output matches Can's faithful Saxony network.
  - **Gotchas:** osmnx caches Overpass responses (`use_cache=False` for honest comparison); overpass-api.de 406s the default python-requests User-Agent.
  - **Artifacts:** `cosmonaut_app/osm/` (new backend, old `osm_downloader.py` kept as reference), `test/test_osm_transform.py` (6 offline contract tests, green), `test/fixtures/overpass_test_aoi.json` (committed fixture), `test/fixtures/compare_osm_backends.py` (spike, `--new-only` for Saxony). `requests` added as explicit dep. Decision: [decisions/20260605-osm-overpass-direct-vs-osmnx.md](decisions/20260605-osm-overpass-direct-vs-osmnx.md).
  - **Next:** swap `upload_tasks.py` import (`cosmonaut_app.osm_downloader` → `cosmonaut_app.osm`), then remove old module; pick deployment Overpass source (wiktorn vs `.pbf`) and promote `OVERPASS_URL` to a strict config var.
- **2026-06-05 (investigation)** — Investigated large-area (Saxony) scaling (GitLab issue #36; branch `36-osm-saxony-is-to-big`). What we know:
  - **OSM build:** the app's `OsmDownloader` (osmnx graph over the convex hull) for all of Saxony **completes but needs ~12.5 GB RAM** (peak 12.1 GB; OOMs below that). Cost scales with hull **area**, not membership-grid density. Cluster worker is limited to 7 GB.
  - **Overpass:** public Overpass rate-limits/blocks Saxony-sized queries. Self-hosted **`wiktorn/overpass-api`** (Geofabrik Saxony extract) works and is **byte-faithful** with osmnx via a one-line `osmnx.settings.overpass_url` change. (`kartoza/docker-osm` rejected: it's PostGIS, osmnx can't query it → would need a road-fetch rewrite + lose fidelity.)
  - **Routing:** `sensor-routing` (all-pairs shortest paths + Ant Colony Optimization over global matrices, O(n²)) is **globally coupled** — a single route can't be tiled/stitched; "many survey-sized jobs" is the path. **Can** (sensor-routing dev) has the Saxony road network and will measure routing RAM/CPU/time at full-Saxony scale.
  - **Direction:** wiktorn (local OSM source, solves Overpass fragility) **+ tiling** (many small jobs, solves scale). Both halves demonstrated individually. Not yet integrated — **waiting on WKDV** before touching the deployment.
  - **Resume steps (after WKDV answers):** (1) if UFZ has an Overpass API → point `osmnx.settings.overpass_url` at it (make env-configurable), no self-hosting; (2) if UFZ has OSM data only → load it into a wiktorn container; (3) if neither → deploy our own wiktorn (Germany Geofabrik extract) as a cosmonaut service. Then in all cases: make `overpass_url` env-configurable, add the overpass service to deployment, scaffold `osm/` in the branch. Open product question for Can: continuous route vs. per-region (tiled) routes.
  - **Local artifacts (scratch, outside repo):** wiktorn at `~/git/cache/wiktorn-overpass/` (Saxony loaded; `docker compose up -d` serves on :12345, instant — init already done). Faithful Saxony road network delivered to Can: `~/git/cache/sachsen/saxony_road_network_EPSG25832.geojson` (+ `.README.txt`).
